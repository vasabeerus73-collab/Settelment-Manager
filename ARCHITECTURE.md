# Settlement Manager v1.0.0-dev

## Runtime architecture

- `scripts/core/` — настройки, реестр контента, миграции, константы
- `scripts/services/` — доменная логика поселения
- `scripts/ui/` — окно ApplicationV2 и регистрация Handlebars-хелперов
- `scripts/integrations/` — сокеты, задел под MATT
- `scripts/api/` — публичный API
- `scripts/utils/` — помощники, не зависящие от нестабильных API Foundry

Поток данных: `content-registry` собирает активный контент (встроенный набор +
включённые паки) → `storage` читает/пишет world-setting и приводит состояние
к схеме → `settlement-service` содержит всю игровую логику → `ui` только
готовит контекст и вызывает сервис.

## Compatibility

Цель: Foundry VTT 13 Stable, build 351.

`compatibility.maximum` намеренно не указан: жёсткий потолок блокирует модуль
на следующей мажорной версии, даже если он там работает.

Модуль не вызывает `foundry.utils.slugify` — такой функции в Foundry нет,
slugify существует только как расширение `String.prototype`. Идентификаторы
генерирует `scripts/utils/ids.js`.

Шаблон использует хелперы `eq`, `and` и `unless`. В API-документации Foundry 13
сравнивающие хелперы не описаны, поэтому `scripts/ui/handlebars-helpers.js`
регистрирует недостающие на хуке `init`, не переопределяя существующие.

## Инварианты, которые легко сломать

- **Состояние читается один раз за операцию.** `canBuild()`, `startConstruction()`
  и рендер списка построек принимают `state` параметром. Если внутри снова вызвать
  `getState()`, появится окно для гонки и рендер начнёт разбирать JSON десятки раз.
- **`state.resources` содержит ключи всех активных ресурсов.** Это обеспечивает
  `mergeState()` в `storage.js`. Без этого арифметика стоимости даёт `NaN`,
  который сериализуется в мир как `null`.
- **Запись в летопись только через `pushChronicle()`** — там проставляются
  обязательные поля и держится лимит `MAX_CHRONICLE_ENTRIES`.
- **Идентификаторы элементов редактора:** `undefined` — «подставь первый»,
  `null` — «создаём новый», строка — конкретный элемент. Путаница этих трёх
  состояний ломает кнопки «Новый …».
- **Слушатели DOM вешаются на конкретные узлы, а не на `this.element`.**
  Корневой элемент переживает перерисовку, делегирование копило бы обработчики.

## Migration

Модуль сохраняет тот же id `settlement-manager` и те же ключи world-setting,
что и ветка 0.x. При первой загрузке ГМом состояние мигрирует до схемы 2
без сброса прогресса. Миграции запускаются **после** `applyCustomPacks()`,
иначе ресурсы из паков не попадут в состояние.

## Проверки

```bash
npm run check
```

Проверяет синтаксис всех скриптов, валидность и согласованность JSON
(включая `data/buildings/*.json`), баланс блоков шаблона, связь всех
`data-action` с зарегистрированными обработчиками и совпадение версий
`module.json` и `package.json`.
